# Phase 5 integrated acceptance

`npm run test:e2e` starts the built companion API and Vite against a fresh temporary SQLite database. An independent Node HTTP client verifies external login, warehouse/item/user setup, Admin/Management/Auditor boundaries, disabled-account rejection, deduction success/replay/conflict/concurrent orders/minimum stock/wrong warehouse, ETag preconditions and local supplier outbox delivery. The API integration suite separately injects a failed deduction-record insert to prove rollback and tests failed supplier dispatch/retry without external sending.

Headless Chromium checks a real browser login, all 12 report rows across server pages, Admin and Auditor report access, supplier status and Auditor read-only UI, two-tab refresh, a 390-pixel mobile viewport, and persistence of Arabic RTL across a full page navigation. Axe checks WCAG 2 A/AA and WCAG 2.1 AA rules on English overview/report, Arabic report/supplier page and mobile/Auditor supplier page; no serious or critical violations were found in those checked views. English and Arabic A4 PDFs were generated using the browser print pipeline, rendered and visually inspected: one page each, all rows and warehouse totals present and legible. Test PDFs and screenshots are ignored local artifacts, not release deliverables.

The selected language is stored as a non-secret preference in `localStorage`. Access and refresh tokens remain in memory and HttpOnly cookies respectively. Browser tests use only fresh temporary credentials and data. No supplier is contacted; `Sent` means recorded by the local adapter. The authenticated health route was implemented in Phase 6. The automated accessibility checks do not replace manual assistive-technology review.
